# Карточки обзора сделок (belfed.ru)

Модальные карточки «Обзор» по каждой сделке на страницах результатов
(`ru/trades.html` — крипта, `ru/equities.html` — акции). Существующий дизайн
страниц, загрузка данных из таблицы, блок статистики и фильтр по годам не
меняются: слой карточек добавляется поверх и полностью изолирован под `.brc-*`.

## Файлы

| Файл | Назначение |
|------|------------|
| `trade-review.js` | Слой модального окна. `window.BelfedReview.attachButton(cell, data)` добавляет кнопку «Обзор» в ячейку столбца «Анализ» и открывает доступное окно (`role="dialog"`, `aria-modal`, закрытие по ESC и по клику на фон, удержание фокуса по Tab, возврат фокуса). Хранилища браузера (localStorage/cookie) не используются. Язык этого зеркала жёстко задан как русский. Ссылка на тестовый доступ: `/ru/trial.html?source=trial_tradehistory_modal_ru`. |
| `trade-review-enrichment.js` | Структурированные вручную подтверждённые блоки логики, риска и расчёта для отдельных сделок. Ищет только collision-safe ключ (`актив#направление#тикер|вход|выход`), вставляет блок между заголовком/метриками и существующей лентой или методологией. |
| `trade-review.css` | Изолированные стили кнопки, окна и содержимого карточки. Наследует цветовые переменные `:root` каждой страницы, глобальных правил не добавляет. |
| `trade_review_cards.json` | Готовый набор карточек, ключ по сделке. Только русские тексты (`{kind, ru}`). Генерируется, вручную не редактируется. |
| `trades-fallback-crypto.json` | Резервный список крипто-сделок (нейтральный по языку) на случай, если таблица недоступна. |

## Как выбирается карточка (одинаково для каждой закрытой сделки, включая будущие)

1. Каждая видимая закрытая строка вызывает `attachButton` со своими полями
   (`ticker, dir, entryDate, exitDate, entryP, exitP, result, tvLink`).
2. По клику модуль ищет сделку в `trade_review_cards.json` по ключу
   `ТИКЕР|ДАТА_ВХОДА|ДАТА_ВЫХОДА` (запасной ключ: `ТИКЕР|ДАТА_ВХОДА`).
   - **Есть в наборе** → готовая карточка: для сделок бота это подробная лента
     событий (вводная приглушённым текстом, дословные сообщения, метки
     «сообщение с сигналом (для подписчиков)» на каждом шаге, призыв к тесту);
     для остальных это обычная карточка (плашка «Исходный анализ», поля сделки,
     блок «Дополнительные комментарии» при наличии, приглушённый блок
     «Методология», призыв к тесту).
   - **Нет в наборе** (например, сделка закрыта после последней сборки) → модуль
     строит обычную запасную карточку из полей самой строки (плашка «Исходный
     анализ» из ссылки TradingView, поля сделки, приглушённая «Методология»,
     призыв к тесту). Лента событий при этом не выдумывается.

Так новые закрытые сделки автоматически получают карточку в согласованном стиле и
по тому же алгоритму без правки кода. Пересоберите набор, чтобы заменить запасную
карточку только что закрытой сделки на подготовленную (и чтобы у сделок бота
появилась подробная лента).

## Приоритет ссылки на исходный анализ

Внутри карточки ссылка «Исходный анализ» ведёт на публичный источник в порядке:
TradingView → X (Twitter) → публичный Telegram. Приватные ссылки Telegram никогда
не подставляются.

## Русский текст и типографика

- Весь интерфейс и пояснения на русском; латиницей остаются только тикеры, ссылки,
  названия брендов и дословные исходные сообщения.
- Короткое тире (en-dash, знак U+2013) в русском тексте не используется. Длинное
  тире «—» в новых пояснениях по возможности заменяется двоеточием, запятой,
  скобками или дефисом; знак «—» допустим лишь как пометка неизвестного значения
  в полях.

## Пересборка набора карточек

Набор для `.ru` получается из общего набора проекта: для каждой сделки берутся
только поля `{kind, ru}`, ссылка на тест приводится к виду
`/ru/trial.html?source=trial_tradehistory_modal_ru`, из русского текста убирается
короткое тире (en-dash, U+2013), а в подготовленных датированных пунктах длинное
тире после года заменяется запятой. Готовый файл кладётся рядом с `trade-review.js` и
`trade-review.css` в каталоге `/ru/`.

Подтверждённые ручные дополнения остаются в `trade-review-enrichment.js`, а не
в генерируемом `trade_review_cards.json`; поэтому ежедневная пересборка
манифеста не перезаписывает их.

## Размещение

Файлы должны лежать в каталоге `/ru/` сайта belfed.ru:

- `/ru/trade-review.js`
- `/ru/trade-review-enrichment.js`
- `/ru/trade-review.css`
- `/ru/trade_review_cards.json`
- `/ru/trades-fallback-crypto.json`

Правки страниц (подключение `<link>`/`<script>` и вызов `attachButton` в цикле
построения строк) уже внесены в `ru/trades.html` и `ru/equities.html`. Менять CSP
не требуется: все ресурсы одного источника и покрыты действующими правилами
`script-src 'self'` / `style-src 'self'` / `connect-src 'self'`.
